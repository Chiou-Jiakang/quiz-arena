# Quiz Arena v0.7.0：排行榜與歷史成績設計

## 範圍

- 首頁提供排行榜入口；前十名按分數由高至低、正確率由高至低、完成時間由早至晚、場次 ID 字典序排名。
- 最近 20 筆歷史成績按完成時間（新到舊）列出，與排行榜排序**不同**。
- 點選歷史成績可讀取該場次的逐題結果。使用純 `textContent` 渲染暱稱、題目及解析，不拼接不可信 HTML。
- 未完成的遊戲不進入排行榜；資料仍儲存在 SQLite。
- API：`GET /api/leaderboard?limit=10`（允許 1–100），回應 `{ "scores": [...] }`。
- 使用既有 `GET /api/scores` 及 `GET /api/scores/:id` 作為歷史成績來源。

## 資料及安全界線

SQLite 對 `results` 全表進行 SQL 排序後才套用 `LIMIT`，避免只排序最近若干筆產生錯誤排行。既有 `results` 表與 Schema 版本不變，不遷移舊資料。

本版仍限本機演示，未實作登入、權限控管、公開部署安全性；任何可訪問本機服務的人都可能看到暱稱與歷史成績。不要輸入敏感個資。

## 驗收

1. `npm test`：原有 60 項不得退化，新增排行榜的單元及 HTTP 測試通過。
2. `npm start`，開啟 `http://127.0.0.1:3000/`，首頁進入排行榜。
3. 尚無成績時顯示空狀態；完成不同分數的遊戲後應按照分數排序；最近成績依完成時間顯示。
4. 檢查逐題回顧、重新整理、離線錯誤訊息、返回首頁。
5. 完成場次跨伺服器重啟仍在列表中；不能把 5500 靜態網站當作全端版。

## 已知限制

- 尚無伺服器端使用者身分認證、暱稱唯一性或反刷榜機制。
- v0.6.0 原有 `GET /api/health` 版本字串與啟動訊息的版本標示不一致，後續可將版本設定集中管理；本功能包保留既有健康檢查契約以避免破壞舊測試。
